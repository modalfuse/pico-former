# Reproducing the tables and figures

This file lists, for every table and figure of the revised manuscript and of its Supplementary Material, the command that produces it, the inputs it reads and the file it writes. Section 4 is ordered by table and figure number; tables that describe the design or summarize other tables are listed with their sources.

Paths are relative to the repository root: `code/` holds the scripts of the revised manuscript and `code/results/` the aggregate results they write; `firmware/` and `host/` are the firmware and host directories. Unless a directory is given, scripts are run from the repository root.

## 0. Local inputs

The three checkpoints are provided in `checkpoints/s<seed>/ceqt.pt`; window caches, raw records, and per-window board arrays are not distributed. The scripts locate the local inputs through these environment variables:

| Variable | Meaning |
| --- | --- |
| `PF_WORKSPACE` | Root of the local workspace. Expected layout: `rice-former/` (RICE-Former v1.0.6 checkout), `runs/20260830_s<seed>/` with `ckpt/ceqt.pt` (a copy of `checkpoints/s<seed>/ceqt.pt`) and `cache/azt1d_s<seed>_str15.pkl` for seeds 20260828–20260830, and `validation/sample512.npz` (indices of the 512-window stratified sample) |
| `RICE_FORMER_SRC` | Optional; overrides `PF_WORKSPACE/rice-former/src` |
| `PICO_GOLD_DIR` | Optional; directory of `window0.json` written by `host/export_golden.py` (default `gold/`) |

Window caches are built with RICE-Former v1.0.6 (AZT1D) and `code/build_external_cache.py` (OhioT1DM, DiaTrend). Weight headers are generated by `host/export_golden.py` (node firmware; it also writes the golden window `gold/window0.json`, which holds participant data and is not distributed), `code/int8/prep_int8_data.py` and `code/int8/quantize_espdl.py` (ESP-DL builds), and `code/design_space/latency_fw/gen_bench_weights.py` (design-space latency builds). Board scripts read the Wi-Fi credentials and the API token from `firmware/wifi.yaml` (copy `firmware/wifi.yaml.example`).

Board replays write `audit.npz` (per-window outputs), `ckpt.npz`, and boot logs next to `audit.json`; only `audit.json` is distributed. Scripts that read `audit.npz` or the boot logs (Tables 5, 6, S5, S12, S13b; Figs. 2 and 4) therefore need the replays of Table 4 to have been run locally. The DiaTrend subsets replayed on the WiFiduino are given by `code/results/r1_1/diatrend17_sample1000.npy` (1,000 windows per participant, seed 20261009) and `diatrend17_second_half.npy` (full-set indices 57,967–115,933).

## 3. Data preparation and builds

```bash
# AZT1D windows (seeds 20260828-20260830): RICE-Former v1.0.6, see its README
# OhioT1DM (12 test subjects) and DiaTrend (17 subjects with basal records)
python code/build_external_cache.py          # -> code/results/external_cache/{ohio,diatrend17}_str15.pkl
python host/export_golden.py                 # -> firmware/include/ceqt_weights.h, gold/ (needs RICE_CKPT, RICE_CACHE)
cd firmware && pio run -e s3_n16r8 -t upload # frozen node firmware
```

The seed 20260829 and 20260830 images (`s3_s20260829`, `s3_s20260830`) read `firmware/include/ceqt_weights_s<seed>.h`: run `host/export_golden.py` with `RICE_CKPT` and `RICE_CACHE` of that seed and with `PICO_FIRMWARE_INCLUDE` and `PICO_GOLD_DIR` set to a separate directory, then copy the exported `ceqt_weights.h` under that name. Test builds are further environments of `firmware/platformio.ini` and differ from `s3_n16r8` only in build flags: `s3_notiming`, `s3_o2`, `s3_nofma` (Section 6.2, Table S13b); `s3_corrupt_w`, `s3_corrupt_t`, `s3_eatsram` (Table S17b); `s3_linkdrop` (Table S7d); `s3_tls_int` (Table S7c); `s3_deploy` (Table S6); `s3_energy` (Table 9).

### 4.1 Energy (Table 6 energy row, Table 9, Supplementary Tables S9a and S9b)

A Nordic Power Profiler Kit II (PPK2, `ppk2-api`) in source mode supplies 3.30 V to the module's 3.3 V rail and samples the current at 100 kS/s; the USB-serial bridge and the on-board regulator are outside the measurement point. GPIO 4, 5, and 6 of the node drive the PPK2 logic inputs D0 (forward pass), D1 (HTTP handler), and D2 (deployment cycle). The node runs `s3_energy`; its stored windows are generated from the AZT1D held-out set and are not committed.

| Result | Command | Output |
| --- | --- | --- |
| Stored windows and energy firmware | `python code/host2/gen_energy_windows.py --n 64`; `cd firmware && pio run -e s3_energy -t upload` | `firmware/include/energy_windows.gen.h` (local) |
| Reset floor (RST tied to GND), three recordings | `python code/host2/ppk2_record.py --tag base_reset --seconds 30 --power-on --power-off-at-end` (tags `base_reset`, `base_reset_r2`, `base_reset_r3`) | `code/results/energy/base_reset*/ppk2/summary.json` |
| E1–E6, three power cycles | `PY=<python> code/host2/run_ppk2_sessions.sh <board ip>` runs `ppk2_session.py --plan short` three times (`energy_short_r1`–`r3`) and `--plan cycles` once (`energy_cycles_r1`) | `code/results/energy/<tag>/steps.jsonl`, `summary.json`, `http.csv`, `ppk2/raw.bin` (local) |
| E7a and E7b, three complete passes each | `python code/host2/ppk2_session.py --tag energy_cycles_r2 --plan cycles --ip <board ip>`; `--tag energy_e7a_r3 --plan e7a`; `--tag energy_e7b_r3 --plan e7b` | as above |
| Per-step pulses and 1 s blocks | `python code/host2/energy_tables.py extract --tag <tag>` for each run (reads `ppk2/raw.bin` and `ppk2/index.csv`) | `code/results/energy/<tag>/ppk2/energy_steps.json` |
| Table 9 and Table S9b | `python code/host2/energy_tables.py tables` (reads only the files in `code/results/energy/`) | `code/results/energy/energy_tables.json` |

The raw recordings (`raw.bin`, 4 bytes per sample, up to 2.7 GB per run) and `index.csv` are not distributed; `energy_steps.json` holds every forward pass, HTTP handler interval, and 1 s block mean that the tables use. `meta.json` keeps the PPK2 calibration of each recording.

Before any wireless test, `route -n get <board ip>` must report the physical Wi-Fi interface; `run_wireless.py` stops if the route goes through a proxy tunnel interface. `wifi.yaml` (network credentials and the API token) is local and is not distributed.
